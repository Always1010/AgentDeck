# AgentDeck — 本地项目 HTML 工作台

按 [V1 规格 1.1](AI_Project_Workbench_V1_1_Implementation_Spec.md) 实现。网页中管理多个项目、原地挂载多个真实目录，直接阅读 HTML 和运行纯前端工具。原文件不搬迁、不改写；新增目录与文件无需重启或重建平台。

## 启动

需要 Node.js 22.12+（本次实际使用 24.20.0）和 npm。首次安装：

```powershell
npm install
npm run dev
```

开发模式使用同一主平台端口与 Vite 中间件，HMR 使用主端口 + 2。正式模式：

```powershell
npm run build
npm start
# 在浏览器打开 http://127.0.0.1:4310
```

已有锁文件的干净安装使用 `npm ci`。`build` 只构建平台，不复制或打包挂载内容。正式服务同时监听回环地址：主平台 **4310**、预览 **4311**。请使用 `127.0.0.1`，严格 Host 校验不接受 localhost 别名。不静默换端口，不监听局域网。

```powershell
npm start -- --state-dir "$env:LOCALAPPDATA\AgentDeck-Test\state"
npm start -- --port 4310 --preview-port 4311
```

默认注册表在 Windows `%LOCALAPPDATA%\AgentDeck\state\registry.json`，其他系统在 `~/.local/share/AgentDeck/state/registry.json`，均位于仓库外。首次使用默认路径启动时，若新注册表不存在，会校验并复制旧 `ProjectWorkbench/registry.json`，保留旧文件和新目录中的 `registry.json.legacy.bak`；指定 `--state-dir` 时不自动迁移。迁移前请停止使用旧注册表的服务。同一个状态目录只运行一个服务实例。状态目录不能位于准备挂载的目录内。退出使用 Ctrl+C。

Windows 试运行可直接从当前仓库安装后台服务：`npm run background:install`，随后访问同一地址。它会构建正式版本、注册当前用户的 **AgentDeck 登录自启动任务**并立即启动，配置和日志留在 `%LOCALAPPDATA%\AgentDeck`。之后修改平台代码用 `npm run background:update` 停止、构建并重新启动；新增挂载/原内容无需执行更新命令。查看状态用 `npm run background:status`。完整命令、路径规则与限制见 [后台运行说明](docs/BACKGROUND.md)。

## 第一次使用与目录管理

1. 点击“添加项目”，输入名称，粘贴本机绝对路径，或打开网页目录选择器逐级浏览盘符/常用位置。
2. 确认真实路径、用途和只读发布范围后保存。它登记的是服务所在电脑的目录，不是浏览器文件上传。
3. 点击左侧项目旁的“管理”，或选中项目后点击“管理项目”，即可移除项目、添加更多互不包含的目录、修改别名/路径、标记工具子目录、停用/恢复或卸载。
4. 项目改名不改变 ID。更换路径需确认；相对路径不变时链接和收藏保持。移除项目或卸载只删除登记，不删除原文件；已加载进浏览器的内容不能被撤回。

同项目重叠目录会被拒绝；已有项目里的 `tools` / `工具` 可直接标记为工具子目录。不同项目登记同一目录时提示共享原文件。一个目录离线不影响其他项目，记录会保留，并每秒检查恢复。

不要挂载系统盘根、用户主目录、系统敏感目录、隐藏敏感目录或包含平台状态的祖先目录。选择可信且适当的输出范围；扩展名过滤无法识别所有秘密。

## 报告与工具

用途有三种：

| 用途 | 目录与行为 |
| --- | --- |
| 项目内容 | 递归发现 HTML、MD、TXT、CSV、JSON；普通根 `index.html` 不遮蔽子报告。可以标记多个不重叠工具子目录。 |
| 工具集合 | 容器中的 HTML 各自成为工具；递归组织目录。每个工具包只有一个默认入口。 |
| 单个工具 | 直接挂载完整 `dist` 或原生工具根；默认 `index.html`，可以选择其他 HTML。 |

工具包优先使用平台入口覆盖，其次 `dist/index.html` / `build/index.html`。两个构建候选同时存在会提示选择；有 `package.json` 而无构建输出会提示待构建。工作台不会运行 npm 或包脚本。工具范围、入口、显示名、分类与刷新偏好只写注册表。

内容列表默认索引 HTML、Markdown 和 CSV；JSON、TXT 不列入列表，但允许在授权范围内作为工具/页面资源访问。预览 URL 保持目录关系，例如 `/m/<mountId>/reports/copper/index.html`，相邻 CSS/JS/图片/字体和 `fetch('./data.json')` 原样访问。支持目录首页补尾斜杠；所有资源 `no-store`；缺失 JS/CSS/JSON 返回错误，不回退为首页。

添加项目时，路径校验与登记写入成功即可返回；目录索引在后台运行，期间显示“扫描中”，完成或失败后更新目录状态。修改某个挂载只重扫该挂载，项目改名不触发重扫。大型项目可在“排除路径”中按相对路径排除无需浏览的目录；深层内容仍需递归查找，因此首次扫描耗时取决于目录数量。

构建工具用相对资源地址，Vite 配置 `base: './'`，SPA 推荐 hash 路由。根绝对 `/assets/...`、history 路由、SSR、开发服务器代理和后端 API 不自动兼容。平台不重写 HTML、不注入统一布局，也没有报告/数据/来源/文件四页签或独立来源面板。

## 阅读和持续更新

- 左侧项目导航，中间入口列表/按需展开文件树，右侧直接显示内容。全局最近更新、全部工具、名称/路径/项目名搜索和收藏可跨项目使用。
- 报告默认自动更新；“更多设置”中可以关闭自动更新并改为提示。自动重载可能重置报告自身交互。
- **工具始终只提示更新**，用户点“加载更新”才重载。其他项目更新不会更换当前 iframe。切换离开、主动刷新或关闭页面仍可能丢失未保存输入；需要长期保留可用独立标签。
- 更新判断采用入口所在目录及子目录的资源范围；根报告使用整个挂载范围。构建工具使用实际输出目录范围；不解析任意 JS/CSS 依赖图，跨范围共享资源可能需要手动刷新。
- Chokidar 等待约 300ms 写入稳定，再合并约 300ms；不保证多文件构建原子性。根 `dist` 删除重建会自动恢复。连接断开时显示重连状态，恢复后重新取得目录/入口列表，当前内容提示手动刷新。
- 工具栏提供关闭预览、刷新、收藏和独立预览；更多设置提供源码/阅读、分类、显示名、入口覆盖、原文复制与下载。顶部始终保留沉浸/退出沉浸入口。
- “新标签”仍是带薄工具栏和更新通知的工作台预览；“打开原始页面”直接访问隔离预览来源，不注入刷新脚本，需要手动刷新。

HTML 打开前检查入口和 HTTP 响应；这不表示已经验证页面内部所有脚本。源码模式不会执行源码文本。Markdown 默认阅读，支持 GFM 表格/代码块、标题锚点、安全相对图片/文档链接；原始 HTML 关闭，危险协议过滤。外部来源链接新标签打开。

CSV/JSON/TXT 是保真原文，不是交互表格或 JSON 树。大整数不经 parse/stringify。文本上限 10 MiB，超限提示下载；静态 HTML/JS 以流式响应提供。文件树中的非入口资源提供下载。

收藏存在主平台 localStorage；清理浏览器数据会丢失收藏，但不会丢失磁盘注册表。文件/工具真实改名可视为移除加新增，不做智能重命名追踪。

## 横屏与竖屏桌面布局

- 横屏使用项目导航、紧凑内容列表和阅读区三栏。拖动列表右侧分隔线调整宽度；键盘聚焦分隔线后，左右方向键微调，Home/End 调到最窄/最宽。
- 窗口宽高比不大于 1，或窗口宽度不大于 1000 CSS px 时，切换为顶部项目导航与内容列表、下方全宽阅读区。适用于竖屏显示器、系统缩放和桌面分屏；不依赖设备型号，不另做移动设备布局。
- 顶部可分别折叠项目导航、内容列表。列表宽度、折叠状态和排序记在当前浏览器；沉浸只临时隐藏导航与列表，退出后恢复原布局。
- 跨屏移动、折叠和沉浸切换不重新挂载预览，不主动刷新内容，保留工具输入与当前滚动位置。内嵌页面仍可自行响应尺寸变化。
- 列表默认按最近更新排序，可改为名称排序；“最近更新”视图固定按更新时间排序。搜索和筛选固定在列表顶部，原始路径和目录状态在“目录与文件”中查看。

## 快捷键

| 按键 | 操作 |
| --- | --- |
| `F` | 进入/退出沉浸；需已打开内容。 |
| `Esc` | 逐层关闭：最上层弹窗 → 更多设置 → 临时搜索 → 沉浸。一次只关闭一层。 |
| `/` | 聚焦当前范围搜索；临时展开已折叠或沉浸中的列表。`Esc` 取消并恢复原搜索与布局；打开结果后恢复原布局。 |
| `↑` / `↓` | 搜索框中向下进入结果；列表内移动焦点，不自动切换内容。 |
| `Enter` | 打开聚焦的结果；搜索框中打开首个结果。 |
| `?` | 显示快捷键帮助。 |

输入框、下拉框、编辑区域和中文输入法组词期间不触发单键快捷键，长按不会反复切换沉浸。“快捷键”面板可关闭 `F`、`/`、`?` 并记住选择；按钮与 `Esc` 仍可使用。工作台不拦截 Ctrl、Alt、Win/Command 组合键，也不占用浏览器 F11 全屏。

快捷键在工作台获得键盘焦点时生效。**跨来源 iframe 中的 HTML 报告和工具不会向外层传递键盘事件**；在其中输入时，可直接点击顶部“退出沉浸”，或先将焦点移回工作台工具栏。未注入脚本、修改报告或放宽预览来源隔离。Markdown 和原文阅读区可直接使用。

构建示例的源码与真实生成的完整 `dist` 已交付，可复现：

```powershell
npm run build:example
```

公司项目使用报告目录和静态输出目录两个互不重叠的挂载。工具集合用于包含多个工具包的父目录；不要把源码工具根误当成集合容器。也可把完整 `dist` 直接挂到其他项目。

可选起点见 [templates](templates/README.md)，Agent 输出约定见 [CONTENT-GUIDE](docs/CONTENT-GUIDE.md)。来源写入报告正文，不需要 `artifact.json` 或 `sources.json`。

## 安全与恢复

这是本地单用户、可信内容工作台。主平台和预览不同来源；严格 Host、Origin/Fetch Metadata、JSON 及非简单请求头保护管理接口；不把管理凭证放进 cookie 或预览 URL。iframe 和预览响应 CSP 限制顶层跳转、表单外发、插件与 Worker；摄像头/麦克风等能力关闭。

默认不跟随 symlink/junction；每次文件/源码/下载请求重校验挂载状态、真实路径和统一排除规则。`.git`、依赖、隐藏配置、常见密钥文件、锁与临时文件不发布。`package.json` 仅用于受限工具识别，不提供给浏览器。用户排除项采用相对文件/目录路径（非 glob），在索引与直接 URL 中同样生效；Windows 下不区分大小写。

所有项目共用预览来源，可能共享浏览器存储并读取其他已公开挂载；**V1 不提供项目间机密隔离，也不适合不可信多用户内容**。可信 HTML 可按浏览器规则联网，平台不提供绕过 CORS 的代理。本地依赖和示例不需要外网；用户 CDN/API 页面仍需联网。PWA/Service Worker 暂不支持。

注册表串行写临时文件并替换，保留 `registry.json.bak`。损坏配置会报错并停止，不覆盖为空表。恢复时先停服务，保留损坏原件，再用确认有效的 `.bak` 替换 `registry.json` 后启动。目录离线可等待磁盘恢复，或在管理界面重新定位路径。不要手工编辑正在运行服务的注册表；多浏览器标签请使用网页 API。
