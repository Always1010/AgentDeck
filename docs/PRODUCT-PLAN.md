# AgentDeck 产品定位与实施方案

更新日期：2026-09-30。本文依据用户确认的实际使用场景替换此前的优化建议。当前行为以 README 和代码为准；下列实施状态随交付更新，不将计划描述为已有功能。

## 初衷与应用场景

AgentDeck 是本机运行、浏览器访问的内容阅读与静态工具工作台。Agent 负责生成 HTML 报告、Markdown 文档和纯前端小工具，AgentDeck 负责让这些成果方便地找到、打开、阅读和持续使用。

1. Agent 用 HTML 展示结论、排版、图表、比较和交互，工作台提供稳定的阅读入口。报告的内容结构和视觉设计由页面自己决定。
2. 本地内容也在浏览器中阅读，方便点击引用网页、查看原始资料，再返回报告继续阅读。来源链接正常使用即可，不预设来源审核或证据管理流程。
3. 多个项目原地挂载各自的真实目录。新增成果不需要搬文件、上传、逐份登记、修改平台源码或重建工作台。
4. 用户也会使用 Agent 制作的文本清理、换算等静态小工具，因此切换页面应保留输入，更新应避免意外刷新正在使用的页面。
5. 多标签、分屏、收藏、阅读位置恢复和更新提醒共同服务于日常反复阅读、对照和使用内容。Markdown 是重要的文档补充，图片和数据预览用于直接查看配套文件。

典型流程：向 Agent 提需求 → 成果写入已有本地目录 → 在工作台打开报告、文档或工具 → 按需打开其他页面或网上资料 → Agent 更新文件后加载新版 → 下次继续原来的阅读现场。

## 产品边界

- 平台只读访问挂载内容；项目登记、个人设置与阅读现场单独保存。
- HTML 自己提供章节、图表、来源与交互。平台不强制模板或元信息协议，不把任意页面重新组织成报告详情页。
- 批注验收、研究专题、证据管理、模型对话、Agent 调度不属于本轮主线，不能因为尚未实现就称为核心缺口。
- 不执行挂载目录中的依赖安装或构建脚本，不把静态工具扩展成任意后端程序运行平台。
- 已完成的多标签、分屏、主题、自动现场恢复、未读更新、Markdown 目录与折叠不重复列为待开发功能。

## 三批实施

### 第一批：日常便利与低风险性能改进

- 复制当前文件完整路径，在文件树中按需定位。
- 重新打开误关标签，恢复文件及可恢复的阅读位置；不承诺恢复已销毁工具的临时输入。
- 图片预览：适应窗口、原尺寸、缩放及下载。
- 收藏/工具列表不可见时暂停可用性检查，恢复可见时核对。
- 取消失去用途的页面加载请求，避免陈旧响应覆盖。

### 第二批：多页面与查找能力

- 快速打开已打开、收藏和工具中的文件；支持用户主动指定挂载目录的文件名/路径搜索，显示范围，限制规模并可取消，不进行启动时全盘正文索引。
- CSV 只读表格、JSON 格式化折叠，保留原文与下载；不丢失 CSV 前导零或 JSON 大整数，对大内容限制预览。
- 恢复现场时只启动可见标签，其他标签首次激活才加载；已经加载的实例继续保留。
- 滚动位置与结构保存分开调度，合并连续保存，保留隐藏/离开时最新位置及存储失败提示。

### 第三批：大目录与长期使用

- 当前 HTML 可选择关注同目录资源变化，明确提示检测范围，合并变化并由用户手动刷新。
- 阅读组合命名、固定、删除和打开；复用已有现场存储，不增加研究管理对象。
- 个人设置、收藏与阅读组合备份恢复；导入校验格式和版本，不导入执行代码，不打包或改写源报告。
- 优化目录枚举的并发和重复工作，保留逐文件访问边界。
- 单文件更新及已读确认直接处理对应记录；合并重复核对，减少无变化状态的序列化。

## 实施与验证原则

主 Agent 负责产品边界、工作台入口、文档和最终集成；前端查看器、阅读现场、后端文件服务可按文件所有权并行实施。公共接口先明确，各功能独立检查和本地提交，不远程推送。

重点回归：HTML/Markdown 正常阅读、相对资源与链接、工具输入保留、多个阅读区独立状态、文件原地只读、目录排除及符号链接边界、更新只确认实际已读版本、旧现场兼容。

性能验证覆盖多标签恢复、长文滚动、大目录读取、隐藏界面请求、批量更新与后台空闲。记录实际样本和结果，不把静态风险或单次测量当成通用性能结论。
