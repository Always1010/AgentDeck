## 为什么重写

上一版重点放在“怎样与 Agent 沟通、怎样交付成果”，这有价值，但没有优先处理用户每天遇到的操作问题：切换文件后找不到原页面，工具输入和阅读位置无法连续保留，也缺少夜间模式。同时，它把帮助、最近访问、数据阅读等不同层次的建议混在一张优先级表中，没有讲清具体场景和先后关系。

这不是用户理解有误，而是上一版的重点和表达没有对齐实际需求。新版保留有用的协作与阅读建议，先完成多页面和主题，再改善日常操作、扩展产品能力。

## 产品要帮助用户完成什么

首要用途是阅读 Agent 生成的 HTML 研究报告。Agent 常用 Markdown 交付文字，但用户希望研究结论、图表、数据对比和来源以更直观的 HTML 页面呈现，因此建设这个应用来集中查看这些报告。Markdown 是编程文档、过程笔记的补充；数据文件与静态工具主要用于辅助核对报告。

上一版“本地文件工作台”的表述过于宽泛，弱化了这个初衷。后续优先级应由报告阅读场景决定，不把通用文件管理或工具平台扩张当作产品目标。

另一项核心目的，是把阅读平台从文件编辑器搬到浏览器。Agent / Codex 的报告、Markdown 和分析资料经常含有引用网页与原始出处；在编辑器阅读时还要反复跳转浏览器核对来源。AgentDeck 让本地报告也在浏览器中展示，读者可以读报告、打开来源网页、核对后回到原来的阅读位置。HTML 的直观展示和浏览器的链接访问能力共同构成产品价值。

因此评估优化的标准是：是否让报告更容易理解、是否方便核对依据、是否减少找回页面和切换工具的成本。来源网页目前使用浏览器标签打开，与工作台里的本地报告标签区分；不把任意外部网站的嵌入阅读当成已实现能力。

Agent 在真实目录生成报告，用户在 AgentDeck 中阅读、核对并反馈修改。文件保留在原位置，工作台只读访问源文件，不自动执行内容目录中的构建脚本。文件树按需展开，旧规格中的递归发现已被后续设计替代，不作为待补功能。

本次升级要让用户同时保留几份成果，来回切换时继续原来的工作，并选择舒适的浅色或深色界面。

## 第一阶段 A：打开多个页面，随时切回去

### 界面安排

右侧预览区顶部增加横向标签栏。左侧所有目录上方增加“已打开页面”，显示同一组页面，可折叠；列表较长时内部滚动，不挤占全部目录空间。切换文件、收藏、工具视图时，已打开页面仍可访问。

```text
顶部：AgentDeck                           主题  使用帮助

左侧                               右侧
已打开页面                         [报告 A ×] [工具 B ×] [临时 C ×]
  报告 A                           当前页面的刷新、收藏等操作
  工具 B                           ───────────────────────────
  临时 C                           页面内容
────────────────
文件 / 收藏 / 工具
筛选框
项目与文件目录
```

### 操作规则

| 操作 | 结果 |
| --- | --- |
| 单击未打开的文件 | 打开临时预览；全工作台最多一个临时标签 |
| 再单击另一个未打开的文件 | 替换临时预览，已保留页面不受影响 |
| 双击文件或临时标签 | 保留该页面，以后不会被其他文件替换 |
| 点击“保留页面” | 和双击相同，适合触屏和键盘操作 |
| 点击已有标签、已打开列表或已打开文件 | 切回已有页面，不重复创建 |
| 关闭标签或已打开列表中的项目 | 同步关闭该页；关闭当前页时优先回到最近使用的剩余页面 |
| 关闭最后一页 | 回到工作台空白页面 |

临时标签使用斜体和明确提示，当前标签高亮。同名文件附带目录信息，悬停可查看完整位置。标签过多时横向滚动，并让当前标签进入视野。浏览器新标签仍是独立打开方式，与工作台内部标签区分。

“保留页面”用于当前工作中的切换，“收藏”用于长期快速找到文件，两者互不代替。临时预览可能被替换，需要保留工具输入时先保留页面。工作台不能可靠检测任意 HTML 中的未保存数据。

### 状态与资源

保留页面之间切换时，HTML 工具输入与运行状态、报告和 Markdown 阅读位置继续保留。刷新只刷新当前页面。后台页面暂停工作台自身的版本检查，重新切入时检查。工具自身脚本仍可能运行，很多复杂工具会增加内存占用；不会为节省内存默默销毁保留页面。

此阶段只保证当前工作台打开期间的状态。浏览器刷新、关闭或重启后不恢复整组页面和工具输入；继续上次工作列入第二阶段。独立页面链接继续能打开指定文件。

### 实施与验收

- 将单个当前文件改为一组打开页面、当前页面和一个可替换的临时页面，沿用挂载 ID 与相对路径定位。
- 切换时隐藏后台预览，关闭或替换时才销毁；键盘事件、更新检查和阅读锚点限定到对应页面。
- 文件树、收藏、工具和文档内链接统一接入页面管理，保留旧链接恢复能力。
- 检查连续单击、双击保留、去重、关闭顺序；两个工具输入与多个文档滚动互不影响；后台停止预览更新轮询；窄屏可切换和保留页面。

## 第一阶段 B：白天和夜间都能舒适使用

顶部提供“跟随系统（默认）”“浅色”“深色”。保存选择；跟随系统时实时响应系统变化；首次显示尽早应用主题，避免先出现大面积错误配色。

主题覆盖文件树、已打开列表、标签栏、工具栏、Markdown、代码与原文、帮助、弹窗、表单、选中和错误状态。统一管理颜色，保证文字清晰、选中明显、焦点可见。切换主题不重载已打开页面。

HTML 报告和工具有自己的配色，也与工作台分属不同来源。此阶段不改写用户 HTML，不强行反转图片和图表。工作台深色不代表任意旧 HTML 都会变黑。第三阶段可为新模板增加配合方式，让支持的报告和工具同步主题。

验收：默认跟随系统；手动选择不被系统变化覆盖；刷新后保留选择；无法保存偏好时仍可在当前会话使用；浅深色下帮助、弹窗和输入框都可读；切换主题保留工具输入。

## 第二阶段：让日常操作更顺手

以下尚未实施，在第一阶段实际使用后再安排。

| 类别 | 使用中的不便 | 建议变化 | 用户如何判断有用 |
| --- | --- | --- | --- |
| 使用体验 | 误关页面要重新找 | 重新打开刚关闭的页面 | 找回入口；不承诺恢复已销毁工具的临时输入 |
| 使用体验 | 第二天要重开一批文件 | 继续上次工作，恢复保留标签和目录展开 | 接着找资料；不承诺恢复任意工具输入 |
| 使用体验 | 从收藏进入后不知道文件在哪里 | 简短路径、复制路径、在目录中定位 | 迅速找到附近的数据和图片 |
| 用户界面 | 字号和密度不适合每个人 | 紧凑／舒适目录密度，Markdown 和文本字号 | 大屏多显示文件，长时间阅读更舒服 |
| 用户界面 | 图标含义和操作范围容易混淆 | 统一名称和提示，区分全局设置与文件操作 | 点击前知道影响哪个页面 |
| 使用体验 | 文件打不开，不知道下一步 | 根据真实错误解释停用、离线、路径失效并提供处理入口 | 知道恢复挂载、修正路径或检查资源 |

“最近访问”暂缓。已打开列表和继续上次工作更直接解决当前需求；以后仍存在跨天找文件的问题时再增加历史列表。筛选继续明确标为已加载文件，不宣传成全目录搜索。

## 第三阶段：围绕报告阅读和来源核验扩展产品

下面都是后续建议，不是已经具备的能力。优先讨论前两项，再按实际阅读需要选择其他项。

| 读者遇到的情况 | 建议落地点 | 做完后是什么样 | 验收与边界 |
| --- | --- | --- | --- |
| 报告很长，结论不好找，引用不好核对 | 提供可选的 HTML 研究报告模板 | 首屏给主要结论；有章节目录、图表、证据和可点击来源；注明资料日期和更新时间 | Agent 填充真实内容，平台不强制改写旧报告；结论可追溯到对应来源 |
| 打开来源网页后还要回去找报告 | 完善引用链接约定与阅读返回体验 | 报告外链在浏览器新标签打开；原报告保留位置；帮助说明如何在来源与报告间往返 | 在模板和实际浏览器中验证新标签与返回；工作台不承诺嵌入任意外部网站 |
| 想比较上周与本周，或两家公司 | 左右对照阅读 | 两份本地报告并排，各自滚动 | 多标签稳定后实施；外部来源网页先用浏览器标签或窗口对照 |
| 多份入口都叫 index.html，不易辨认 | 简化报告显示名称操作，评估专门的报告列表 | 看名称就能分清报告主题 | 当前已有显示名称设置；新界面复用它，不默认递归扫描所有文件 |
| 工作台深色，报告仍白底 | 报告模板支持主题配合 | 支持适配的报告也能夜间阅读 | 不强行反色图片与图表；旧页面逐步适配 |
| Agent 改好了，不知道改了哪里 | 模板提供更新时间和简短修改说明 | 先知道变化，再手动加载更新 | 说明由 Agent 写入；自动历史快照与版本对比另行评估 |
| 图表单位或结论有问题，要反馈 | 从当前报告整理修改要求 | 带上路径，填写章节、问题、期望和需要保留的内容，再复制给 Agent | 不自动发送；复用现有任务模板，稳定要求可整理为项目说明 |
| 需要核对报告引用的数据附件 | 数据和图片阅读增强 | CSV 表格、JSON 格式化与折叠、图片预览 | 后置；保留原文与下载，限制大文件，不损失原始数值 |

这里保留了上一版的“与 Agent 协作”和“数据阅读”，但它们服务于报告核验，而不是另建一个通用工具平台。帮助已交付，只随实际功能补充；不会为了功能数量扩大范围。
