## AD-021 — 沉浸模式只隐藏侧栏，无法专注当前文件

- 日期：2026-09-22
- 状态：已解决
- 现象：进入沉浸后，顶部栏、其他阅读区、文件标签和工具栏仍可见；侧栏预先收起时几乎看不出变化。
- 原因：沉浸状态仅参与侧栏隐藏，阅读布局仍按分屏或最大化状态绘制，没有隐藏文件以外的工作台控件。
- 解决方案：沉浸时让当前阅读区占满浏览器内容区，隐藏其他区域及工作台控件；退出时使用未修改的分屏、最大化与侧栏状态恢复，提供右上角退出按钮。
- 验证：Edge 浏览器检查单屏和多屏、普通最大化、HTML 与 Markdown、输入与滚动保留、快捷键及刷新恢复；类型与自动化测试见 TEST-RESULTS.md。
- 相关文件：`app/web/App.tsx`、`app/web/ReadingLayout.tsx`、`app/web/style.css`、`tests/e2e/immersion.spec.ts`。


## AD-001 — 预览响应检查被主平台 CSP 拦截

- 日期：2026-09-21
- 状态：已解决
- 现象：M2 加入入口 HEAD 检查后，正式模式浏览器无法打开 HTML，工具输入定位超时。
- 原因：主平台 `connect-src` 仅允许自身，未允许向独立预览来源检查响应；iframe 嵌入许可不等于 fetch 许可。
- 解决方案：仅将确定的预览来源加入主平台 `connect-src`；预览服务只向主平台返回 CORS 许可，管理接口仍拒绝预览来源。
- 验证：正式模式 Playwright 测试操作原生及构建工具，并检查隔离访问；实际运行结果见 TEST-RESULTS.md。
- 相关文件：`app/server/server.ts`、`app/web/Viewer.tsx`、`tests/e2e/workbench.spec.ts`。

## AD-003 — 敏感目录作为挂载根时绕过相对文件过滤

- 日期：2026-09-21
- 状态：已解决
- 现象：安全测试确认可以直接登记 `.git` 目录，此时内部普通 TXT 不再带有 `.git` 相对前缀；平台状态的祖先目录也可被登记。

## AD-006 — 千文件规模更新延迟超过目标

- 日期：2026-09-21
- 状态：已解决

## AD-015 — HTML 桥接初版注入改写非 UTF-8 字节且 HEAD 读取完整文件

- 日期：2026-09-22
- 状态：已解决
- 现象：本轮新增 HTML 桥接的初版实现将所有 HTML 按 UTF-8 解码后重新编码，GBK 等编码中的原字节被替换字符破坏；HEAD 元数据检查也完整读取和构造 HTML 响应。此问题在本轮实现审查中确认，不是历史用户问题。
- 原因：注入流程使用 `fs.readFile(file, 'utf8')` 并统一构造 UTF-8 Buffer，GET 与 HEAD 共用完整文件转换；固定响应 charset 也会覆盖原页面声明。
- 解决方案：仅扫描最多 64 KiB 文档前缀确定插入点，以原编码的脚本字节拼接原始文件并流式输出；尊重真实 charset 声明与 UTF-16 BOM。HEAD 只读取有限前缀计算一致的 Content-Length，过长且无法完整确认的 prolog 保持原文。
- 验证：单元测试覆盖 GBK、UTF-16 大小端、BOM、注释和脚本内伪 charset 声明、长文件流式输出；HTTP 回归确认 GET/HEAD 长度一致、下载原字节不变，以及原服务安全边界。
- 相关文件：app/server/html-bridge.ts、app/server/server.ts、tests/html-bridge.test.ts。

## AD-016 — 已接管按键的释放事件仍触发 HTML 自身快捷键

- 日期：2026-09-22
- 状态：已解决
- 现象：本轮 HTML 快捷键桥接初版仅拦截 keydown；HTML 若在 keyup 绑定相同按键，按一次工作台快捷键仍可能触发网页操作，例如历史已经到头时 Alt＋← 被工作台处理后，网页仍收到 ArrowLeft 的 keyup。

- 状态：已解决
- 现象：刷新或重新打开工作台后，打开的文件标签、固定状态、区域历史和阅读位置丢失；布局方向和比例采用跨标签共享偏好，多个工作台页面无法独立保存现场。
- 原因：阅读区及标签仅保存在 React 内存状态中，滚动位置仅存于 ref；通用 localStorage 偏好监听 storage 事件，将布局同步到其他页面。仅保存当前 entry 地址不能重建完整现场。
- 解决方案：每个浏览器标签绑定独立现场 ID，通过 IndexedDB 事务保存布局树、区域标签与历史、显示状态、目录展开和可获取的文档滚动位置。URL 携带现场 ID，刷新及原地址重开恢复；活动现场重复打开时复制为独立副本，Web Locks 保证单一写入者。取得旧现场写入权后重新读取最新快照，避免关闭与重开竞态覆盖最后保存。初始化先校验再启用保存，写入失败保留原快照并提示。隐藏区域在首次可见时恢复滚动，避免最大化状态刷新后位置归零。设置提供最近现场恢复入口。
- 验证：单元测试覆盖快照校验、串行保存、失败重试、所有权交接竞态、前台最近使用与无锁降级；真实浏览器覆盖混合分屏刷新、比例与固定标签、历史与滚动恢复、多页面复制隔离、关闭重开、HTML 隐藏区域恢复、最近现场、指定文件链接及存储不可用降级。完整回归与复验结果记录在 docs/TEST-RESULTS.md。

## AD-024 — 长 Markdown 目录未展开到阅读区底部

- 日期：2026-09-27
- 状态：已解决
- 现象：Markdown 浮动目录的可滚动区域最多只有 440px；在高窗口和长目录中，面板提前结束，无法利用下方阅读空间。
- 原因：目录导航使用固定的 `440px` 最大高度，并以整个浏览器视口作为备用高度，没有按当前阅读区的实际高度计算；分屏后也无法可靠确定各目录可用空间。
- 解决方案：使用 ResizeObserver 跟踪每个 Markdown 所属阅读区的实际高度，通过局部 CSS 变量将目录最大高度设置为阅读区高度减去上下各 18px；目录改为纵向弹性布局，标题与工具栏固定，标题列表占用剩余空间并独立滚动。
- 验证：类型检查和生产构建通过；单元测试 13 项通过；Playwright 使用超过 30 个标题的长目录验证单阅读区及上下分屏中目录底部均与阅读区保持 18px 间距，并回归目录动画、跳转和正文折叠。

## AD-025 — Windows 失效目录监听导致后台持续占满一个逻辑核心

- 日期：2026-09-29
- 状态：已解决
- 现象：后台无网页连接、无扫描任务时，连续 60 秒占用整机 CPU 约 6.23%（16 个逻辑处理器，相当于单核满载）；进程持有两个已删除对象的句柄，且持续发生大量其他 I/O 操作。
- 原因：现用 Node/libuv 的 Windows 目录监听存在删除目录后重复发出绝对路径通知的已知缺陷（nodejs/node#61398、libuv/libuv#5013）；应用将非法路径通知直接忽略，未关闭失效监听。目录监听仅按路径去重，未校验删除重建后的对象身份，周期扫描也没有清理遍历中已消失的子目录监听，缺少通知风暴保护。
- 解决方案：异常路径、自身重命名通知、监听错误和每秒超过 1024 次通知时，同步关闭对应目录及子目录监听；核对原授权范围，并在 30 秒冷却后重新核对和监听。按设备、文件标识和创建时间替换同路径的新目录监听；扫描后清理已消失目录监听，保留不可访问子树的记录。通过监听实例身份忽略旧回调；停用、排除、移除挂载和关闭服务时清理恢复计时器。
- 验证：类型检查、生产构建及全部 92 项单元测试通过，其中 14 项监听器回归覆盖异常字符串/Buffer 路径、越界保护、通知风暴、冷却恢复、过期回调、目录删除重建和生命周期清理。实际 Windows 目录反复删除重建测试确认静置后单核 CPU 低于 25% 的回归预算，且正常新增文件仍通过原生通知发现。正式后台更新后，等待初始化核对完成，连续采样 120.29 秒累计 CPU 时间 0.4531 秒，16 个逻辑处理器折算整机平均 0.0235%（修复前约 6.23%）；采样结束时扫描空闲且无错误。
- 相关文件：app/server/updates.ts、tests/file-update-watchers.test.ts、tests/file-updates.test.ts、README.md。

## AD-027 — 过期源码读取可能覆盖刷新后的查看状态

- 现象：HTML 的“查看源码”读取尚未完成时刷新，较晚返回的旧源码可能覆盖新加载的文本与版本，并把查看器切回源码模式；关闭或替换页面后，旧加载仍继续读取。

- 验证方式：`node node_modules/typescript/bin/tsc --noEmit` 通过；定向 Vitest 2 项通过，覆盖替代读取取消、过期结果守卫与 API 信号透传。新增浏览器回归覆盖“源码读取中刷新”，待统一构建后执行。
