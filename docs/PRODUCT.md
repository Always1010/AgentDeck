# AgentDeck 产品定位

更新日期：2026-09-30。本文说明 AgentDeck 长期服务的使用场景和产品边界；当前操作方式以 README、应用内帮助和实际代码为准。

## 初衷与应用场景

AgentDeck 是本机运行、浏览器访问的内容阅读与静态工具工作台。Agent 负责生成 HTML 报告、Markdown 文档和纯前端小工具，AgentDeck 负责让这些成果方便地找到、打开、阅读和持续使用。

1. Agent 用 HTML 展示结论、排版、图表、比较和交互，工作台提供稳定的阅读入口；内容结构和视觉设计由页面自己决定。
2. 本地内容也在浏览器中阅读，用户可以点击引用网页、查看原始资料，再返回报告继续阅读。
3. 多个项目原地挂载各自的真实目录。新增成果不需要搬文件、上传、逐份登记、修改平台源码或重建工作台。
4. Agent 制作的文本清理、换算等静态小工具可以直接使用；切换页面应保留输入，更新应避免意外刷新正在使用的页面。
5. 多标签、分屏、收藏、阅读位置恢复、更新提醒和个人备份服务于日常反复阅读、对照和使用内容。

典型流程：向 Agent 提需求 → 成果写入已有本地目录 → 在工作台打开报告、文档或工具 → 按需打开其他页面或网上资料 → Agent 更新文件后加载新版 → 下次继续原来的阅读现场。

## 产品原则

- 原文件留在原目录，平台对挂载内容只读；项目登记、个人设置与阅读现场单独保存。
- 按需读取目录和文件，不要求统一成果仓库、清单文件或常驻全文索引。
- 已加载的工具和报告尽量保持实例，避免切换、布局调整和无关更新破坏页面状态。
- 文件更新先提示或按明确偏好处理，不把“发现变化”等同于自动销毁当前页面。
- 图片和数据预览用于方便检查配套文件，原文与下载始终是可追溯兜底。
- 安全边界围绕本机单用户和可信挂载目录设计，不把本地工作台描述成多用户发布平台。

## 产品边界

- HTML 自己提供章节、图表、来源与交互；平台不强制报告模板或元信息协议。
- 来源链接按普通网页链接使用，不预设来源审核、证据管理或批注验收流程。
- 平台不提供模型对话、Agent 调度、研究专题管理或任意后端程序运行环境。
- 不执行挂载目录中的依赖安装和构建脚本；构建型工具应先由其项目生成静态产物。
- 所有项目共用本机预览来源，不保证彼此不信任的项目之间实现机密隔离。
- PDF、Office、全文检索、智能重命名追踪和原子多文件发布不属于当前核心能力。
